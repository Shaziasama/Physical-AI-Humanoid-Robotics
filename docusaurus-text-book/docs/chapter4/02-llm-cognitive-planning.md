# Module 2: LLM-Powered Cognitive Planning

We've successfully converted a user's spoken words into a structured command like `{"intent": "FETCH", "object": "red apple"}`. Now comes the most challenging part: how does the robot figure out the *sequence of steps* required to fulfill this command?

- It needs to locate the apple.
- It needs to navigate to the apple.
- It needs to identify the correct grasping pose for the apple.
- It needs to move its arm to pick it up.
- It needs to bring it back to the user.

This is not a simple, fixed algorithm; it's a dynamic planning process that depends on the state of the world. This is where a **Large Language Model (LLM)** can be used not just for parsing language, but as the robot's core **cognitive engine**.

---

## 1. The LLM as a Sequence Planner

The core idea is to treat the LLM as a "common-sense" planner. We give it a high-level goal and a description of the current world state, and we ask it to produce a high-level plan (a sequence of actions) to achieve the goal.

We can achieve this through clever **prompt engineering**. We design a prompt that gives the LLM all the context it needs to act as a robot's brain.

**The Cognitive Architecture:**

```text
                                  ┌───────────────────┐
                                  │   User Command    │
                                  │(from Whisper/NLU) │
                                  └─────────┬─────────┘
                                            │
                                            ▼
                  ┌───────────────────────────────────────────┐
                  │          LLM Cognitive Agent              │ (ROS 2 Node)
                  │                                           │
                  │   1. Build a "World State" prompt         │
                  │   2. Query LLM for a high-level plan      │
                  │   3. Execute plan step-by-step            │
                  │   4. Update state & re-plan if necessary  │
                  │                                           │
                  └────┬───────────────────────┬──────────────┘
                       │                       │
 (Perception In)       │                       │ (Action Out)
                       ▼                       ▼
┌────────────────────┐ │ ┌──────────────────┐  │ ┌───────────────────┐
│  Vision System     │ │ │   Navigation     │  └▶│    Manipulation   │
│ (Object Detection) │─┘ │   (Nav2)         │    │ (Arm Controller)  │
└────────────────────┘   └──────────────────┘    └───────────────────┘
```

---

## 2. Crafting the Master Prompt

The prompt is everything. It needs to define the "rules of the game" for the LLM. A typical prompt for a robotics LLM-agent has several parts:

**Part 1: The System Preamble**
This tells the LLM its role and capabilities.

> You are a helpful AI assistant acting as the cognitive core for a humanoid robot. Your goal is to generate a sequence of actions to fulfill a user's command.
> You have access to the following functions, which are the robot's primitive skills:
> - `NAVIGATE(location)`: Moves the robot to a known location (e.g., 'table', 'kitchen_counter').
> - `DETECT(object_name, object_color)`: Runs the vision system to find a specific object. Returns the object's ID and position if found, otherwise returns 'Not found'.
> - `GRASP(object_ID)`: Moves the arm to pick up the object with the given ID.
> - `GOTO(position)`: Moves the robot to a specific XYZ coordinate.
> - `PLACE(object_ID, location)`: Places the held object at a location.
> - `RESPOND(text_to_speak)`: Speaks a message to the user.

**Part 2: The World State**
This section is dynamically generated by the Cognitive Agent node. The node gathers information from all other parts of the ROS system (perception, navigation, etc.) and formats it as text.

> ## Current World State:
> - Robot's current location: 'living_room'
> - Objects currently detected:
>   - object_ID: 'obj_1', name: 'cup', color: 'blue', location: 'table'
>   - object_ID: 'obj_2', name: 'apple', color: 'green', location: 'table'
> - Robot's gripper status: 'empty'

**Part 3: The User Command**
This is the command that came from our Voice-to-Action pipeline.

> ## User Command:
> "Bring me the red apple."

**Part 4: The Request**
This tells the LLM what to do.

> Based on the current world state and the user command, provide a JSON-formatted list of functions to execute. If you cannot fulfill the request, use the RESPOND function to explain why.

---

## 3. The LLM's Plan as Output

Given the prompt above, the LLM would reason as follows:
1.  The user wants a "red apple."
2.  I see a "green apple" on the table, but no "red apple."
3.  Therefore, I cannot fulfill the request directly.
4.  The correct course of action is to inform the user.

The LLM would then return the following JSON:
```json
[
  {
    "function": "RESPOND",
    "parameters": {
      "text_to_speak": "I'm sorry, I can only see a green apple on the table, not a red one. Should I bring you the green apple instead?"
    }
  }
]
```

The Cognitive Agent node receives this JSON, parses it, and calls the appropriate ROS 2 service or action to make the robot speak the response.

### A More Complex Example

Let's say the world state was different:

> ## Current World State:
> - Robot's current location: 'living_room'
> - Objects currently detected: []
> - Robot's gripper status: 'empty'
>
> ## User Command:
> "Bring me the red apple from the table."

The LLM's reasoning would be:
1.  The user wants a "red apple" from the "table."
2.  I don't see any objects right now because I'm in the "living_room."
3.  First, I need to go to the "table."
4.  Then, I need to look for the "red apple."
5.  If I find it, I need to grasp it.
6.  Then, I need to return to the user (whose location I might need to ask for, or assume is the 'living_room').

The LLM would then generate a multi-step plan:
```json
[
  {
    "function": "NAVIGATE",
    "parameters": {
      "location": "table"
    }
  },
  {
    "function": "DETECT",
    "parameters": {
      "object_name": "apple",
      "object_color": "red"
    }
  },
  {
    "function": "GRASP",
    "parameters": {
      "object_ID": "result_from_DETECT"
    }
  },
  {
    "function": "NAVIGATE",
    "parameters": {
      "location": "living_room"
    }
  },
  {
    "function": "RESPOND",
    "parameters": {
      "text_to_speak": "Here is your red apple."
    }
  }
]
```

The Cognitive Agent executes this plan step-by-step. It first calls the `NAVIGATE` action server and waits for it to complete. Then, it calls the `DETECT` service. If `DETECT` succeeds, it uses the returned `object_ID` to call the `GRASP` action. This loop of **Plan -> Execute -> Perceive -> Re-plan** is the essence of a cognitive architecture.

By using an LLM in this way, we are offloading the complex, "common-sense" reasoning and planning to the model, while keeping the robot's actual capabilities (its "primitive skills") as robust, well-defined ROS 2 actions and services. This creates a powerful and flexible system where we can add new skills simply by defining them in the LLM's prompt and creating a corresponding ROS 2 node to implement them.
